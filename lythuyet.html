CÂU 1: PHÂN BIỆT POSITION RELATIVE VÀ ABSOLUTE TRONG CSS

1. Khái niệm và nguyên lý hoạt động

Thuộc tính position trong CSS được sử dụng để xác định phương thức định vị cho một phần tử HTML trên trang web:

  • position: relative (Định vị tương đối): Phần tử vẫn nằm nguyên trong luồng tài liệu tự nhiên (normal document flow) của trang web. Không gian ban đầu của nó vẫn được bảo lưu trọn vẹn (các phần tử xung quanh không bị dồn lên hay xô lệch). Khi áp dụng các thuộc tính top, right, bottom, left, phần tử sẽ dịch chuyển so với vị trí gốc ban đầu của chính nó. Đặc biệt, thuộc tính này thường được dùng trên phần tử cha để làm mốc tọa độ gốc (tọa độ 0,0) cho các phần tử con bên trong.
  • position: absolute (Định vị tuyệt đối): Phần tử sẽ hoàn toàn bị rút khỏi luồng tài liệu thông thường (out of flow). Phần tử xung quanh sẽ lấp vào vị trí trống của nó như thể nó chưa từng tồn tại. Phần tử này sẽ được căn tọa độ theo phần tử tổ tiên gần nhất có thuộc tính position khác static (thường là cha có relative). Nếu không tìm thấy phần tử cha/tổ tiên nào có thuộc tính position hợp lệ, nó sẽ định vị theo khung nhìn màn hình (viewport / thẻ <body> hoặc <html>).

2. Ví dụ thực tế: Đặt nhãn giảm giá "Sale 50%" lên góc ảnh sản phẩm

Kỹ thuật chuẩn trong thiết kế giao diện thương mại điện tử là: Thẻ cha chứa ảnh đặt position: relative, và thẻ con chứa nhãn Sale đặt position: absolute với top: 10px; right: 10px;.

<!-- Cấu trúc HTML --> <div class="product-card"> <span class="badge-sale">SALE 50%</span> <img src="laptop.jpg" alt="Laptop Gaming" class="product-img"> <div class="product-body"> <h3>Laptop Gaming Legion 5</h3> <p>Giá: 22.990.000 VNĐ</p> </div> </div> /* Cấu trúc CSS tương ứng */ .product-card { position: relative; /* Đặt làm mốc tọa độ cố định cho thẻ con bên trong */ width: 300px; border: 1px solid #e2e8f0; border-radius: 8px; overflow: hidden; padding: 15px; background: #ffffff; } .badge-sale { position: absolute; /* Rút khỏi luồng, bám theo góc của .product-card */ top: 10px; right: 10px; background-color: #ef4444; /* Màu đỏ nổi bật */ color: #ffffff; font-weight: bold; font-size: 0.8rem; padding: 4px 10px; border-radius: 4px; z-index: 10; }

Minh họa trực quan hoạt động:

SALE -50%
💻
Thẻ cha (position: relative)
Nhãn SALE (position: absolute) bám chặt góc trên bên phải

3. Giải thích ảnh hưởng khi deploy thực tế

Nếu sinh viên quên khai báo position: relative ở khung thẻ cha, điều gì sẽ xảy ra?

Khi không có thẻ cha làm mốc tọa độ, nhãn badge-sale (đang mang position: absolute) sẽ tiếp tục tìm kiếm ngược lên cây DOM cho tới khi chạm đến thẻ <body> hoặc khung nhìn màn hình (viewport). Hậu quả thực tế khi deploy lên hosting là:

  • Khi mở trên các kích thước màn hình khác nhau (Desktop, Laptop 14 inch, iPad hay Smartphone), các nhãn "SALE" của tất cả các sản phẩm sẽ bay dồn hết lên góc trên cùng của toàn bộ trang web hoặc trôi nổi lệch lạc khỏi sản phẩm.
  • Khi cuộn trang web (scroll), giao diện bị vỡ nát hoàn toàn, gây trải nghiệm người dùng rất tệ hại.
  • Do đó, quy tắc vàng trong CSS luôn là: "Muốn con absolute chuẩn xác ở đâu thì phải đặt relative ngay tại cha chứa nó!"

CÂU 2: QUY TRÌNH ĐĂNG KÝ DOMAIN & TRỎ HOSTING CHO WEB TĨNH, RỦI RO BẢO MẬT

1. Quy trình đăng ký Domain và trỏ Hosting cho Website tĩnh

Để đưa một website tĩnh gồm HTML, CSS, JavaScript lên Internet cho mọi người cùng truy cập, quy trình chuẩn gồm 3 bước cơ bản sau:

  1. Bước 1: Mua / Đăng ký tên miền (Domain Name):
    Sinh viên lựa chọn và đăng ký tên miền mong muốn (ví dụ: nguyengiabao.id.vn hoặc myweb.com) tại các nhà cung cấp tên miền (Registrar) uy tín như Namecheap, GoDaddy, PA Vietnam, Mắt Bão.
  2. Bước 2: Mua / Đăng ký không gian lưu trữ (Hosting / Static Storage):
    Tạo tài khoản lưu trữ mã nguồn tĩnh (HTML/CSS/JS/Ảnh). Hosting sẽ cấp cho người dùng một địa chỉ IP máy chủ (IPv4) hoặc một địa chỉ định danh (Domain đích).
  3. Bước 3: Cấu hình hệ thống phân giải tên miền (DNS - Domain Name System):
    Truy cập vào trang quản trị DNS của Tên miền để tạo các bản ghi (DNS Records) trỏ về Hosting:
    • Bản ghi A (Address Record): Dùng để trỏ trực tiếp tên miền gốc (ký hiệu @) tới địa chỉ IP thực tế của máy chủ hosting (ví dụ: 185.199.108.153 của GitHub Pages).
    • Bản ghi CNAME (Canonical Name Record): Dùng để trỏ một tên miền phụ (subdomain như www) tới tên miền máy chủ lưu trữ (ví dụ: username.github.io).

2. Bản chất của DNS (Hệ thống phân giải tên miền)

DNS (Domain Name System) có thể hiểu một cách trực quan giống như "cuốn danh bạ điện thoại của toàn bộ mạng Internet":

  • Máy tính và các thiết bị mạng chỉ hiểu và giao tiếp với nhau bằng những con số địa chỉ IP khô khan (ví dụ: 142.250.190.46).
  • Con người chúng ta thì chỉ có thể ghi nhớ những tên miền thân thiện, có ý nghĩa bằng chữ cái (như google.com).
  • Khi người dùng gõ tên miền vào thanh địa chỉ trình duyệt, máy chủ DNS sẽ nhanh chóng "tra danh bạ" để dịch tên miền đó thành địa chỉ IP chính xác của máy chủ lưu trữ web để trình duyệt gửi yêu cầu tải dữ liệu về.

3. Hai công cụ Deploy Web tĩnh miễn phí không cần Server riêng

Đối với các dự án web tĩnh thuần HTML5, CSS3, JavaScript, sinh viên không cần thuê máy chủ VPS đắt đỏ mà có thể sử dụng các nền tảng tự động hóa CI/CD miễn phí hàng đầu:

  • 1. GitHub Pages: Dịch vụ lưu trữ trực tiếp từ kho lưu trữ Git (Repository). Mỗi khi sinh viên commit và push code lên nhánh main, website sẽ tự động được build và xuất bản công khai dưới dạng link https://username.github.io/repository-name/. Hỗ trợ sẵn chứng chỉ bảo mật HTTPS miễn phí.
  • 2. Netlify: Nền tảng chuyên dụng cho ứng dụng Jamstack và web tĩnh. Cho phép người dùng kéo thả thư mục code vào giao diện web hoặc liên kết tài khoản GitHub/GitLab. Netlify hỗ trợ mạng phân phối nội dung toàn cầu (Global CDN), tự động cấp chứng chỉ SSL Let's Encrypt và cung cấp xem trước bản deploy (Deploy Preview) rất trực quan.

4. Các rủi ro bảo mật nghiêm trọng nếu cấu hình DNS sai

  • Website bị chèn mã độc / chuyển hướng giả mạo (Phishing): Nếu trỏ nhầm bản ghi A sang IP của một máy chủ độc hại hoặc bị hacker tấn công nhiễm độc bộ nhớ đệm DNS (DNS Cache Poisoning), người dùng truy cập trang web sẽ bị dẫn tới các trang lừa đảo đánh cắp tài khoản ngân hàng hoặc mật khẩu.
  • Thiếu chứng chỉ bảo mật SSL/TLS (Không có HTTPS): Dữ liệu truyền tải giữa người dùng và máy chủ dưới dạng văn bản thuần (plain text). Kẻ gian cùng mạng Wi-Fi công cộng có thể dễ dàng bắt trọn gói tin (Man-in-the-Middle - MITM) để đọc trộm tài khoản, cookie, mật khẩu, đồng thời trình duyệt sẽ gắn nhãn cảnh báo đỏ "Không an toàn" (Not Secure).
  • Nguy cơ bị cướp tên miền phụ (Subdomain Takeover): Xảy ra khi quản trị viên tạo một bản ghi CNAME trỏ tên miền phụ (ví dụ blog.mycompany.com) tới một dịch vụ bên thứ ba (như GitHub Pages, S3 Bucket, Heroku) nhưng sau đó ngừng sử dụng hoặc xóa tài khoản ở dịch vụ đó mà quên không xóa bản ghi CNAME. Hacker có thể đăng ký đúng tên dự án đó trên nền tảng thứ ba và toàn quyền chiếm đoạt tên miền phụ của doanh nghiệp để phát tán mã độc.

CÂU 3: SO SÁNH LET, CONST, VAR - CƠ CHẾ HOISTING & HƯỚNG DẪN DEBUG DEVTOOLS

1. Bảng so sánh chi tiết giữa let, const và var

Tiêu chí so sánh var (ES5 trở về trước) let (Từ ES6 - 2015) const (Từ ES6 - 2015)
Phạm vi truy cập (Scope) Function Scope: Có hiệu lực trong toàn bộ hàm chứa nó; nếu khai báo ngoài hàm sẽ là biến toàn cục (Global - gắn vào đối tượng window). Không bị giới hạn bởi cặp ngoặc nhọn {}. Block Scope: Bị giới hạn nghiêm ngặt trong khối ngoặc nhọn {} gần nhất (như khối lệnh if, for, while). Block Scope: Tương tự như let, chỉ có phạm vi sử dụng bên trong khối ngoặc nhọn {} nơi nó được định nghĩa.
Gán lại giá trị (Re-assignment) Cho phép gán lại thoải mái, và cho phép khai báo lại cùng tên biến trong cùng phạm vi. Cho phép gán lại giá trị mới. Nhưng không cho phép khai báo lại cùng tên trong cùng một Scope. Không cho phép gán lại giá trị nguyên thủy (báo lỗi TypeError). Đối với Object/Array, vẫn sửa đổi được thuộc tính bên trong.
Cơ chế Hoisting Được đưa lên đầu phạm vi và tự động khởi tạo giá trị undefined. Không gây lỗi nếu gọi trước khi khai báo. Được hoist lên đầu nhưng không khởi tạo. Nằm trong vùng chết tạm thời (TDZ). Gọi trước sẽ văng lỗi ReferenceError. Tương tự let, nằm trong vùng chết tạm thời (TDZ). Gọi trước khai báo sẽ văng lỗi ReferenceError. Bắt buộc phải gán giá trị ngay khi khai báo.

2. Khái niệm Hoisting và Temporal Dead Zone (TDZ)

Hoisting là cơ chế của trình biên dịch JavaScript: trước khi chạy code, JavaScript Engine sẽ quét qua toàn bộ mã nguồn và đưa phần khai báo của các hàm và biến lên đầu phạm vi (scope) tương ứng.

  • Với var: biến được hoist lên và tự động gán giá trị undefined.
  • Với let và const: biến vẫn được hoist lên đầu phạm vi, nhưng chưa được cấp phát giá trị. Khoảng thời gian từ lúc bước vào khối phạm vi (block scope) cho tới dòng lệnh thực sự gán giá trị cho biến được gọi là Temporal Dead Zone (TDZ - Vùng chết tạm thời). Mọi hành vi cố gắng đọc hay ghi vào biến khi nó đang nằm trong TDZ đều sẽ bị trình duyệt ném ra ngoại lệ Uncaught ReferenceError: Cannot access 'x' before initialization.

3. Ví dụ kinh điển: Lỗi dùng var trong vòng lặp for với setTimeout()

// ====== 1. ĐOẠN CODE BỊ LỖI KHI DÙNG VAR ====== for (var i = 0; i < 3; i++) { setTimeout(function () { console.log("Giá trị của i (dùng var):", i); }, 1000); } // KẾT QUẢ IN RA CONSOLE SAU 1 GIÂY: // Giá trị của i (dùng var): 3 // Giá trị của i (dùng var): 3 // Giá trị của i (dùng var): 3 // GIẢI THÍCH: Do 'var' không có Block Scope mà có Function/Global Scope. // Cả 3 lần lặp đều chia sẻ chung DUY NHẤT một biến 'i' ở bộ nhớ. // Sau 1 giây khi hàm callback trong setTimeout chạy, vòng lặp đã kết thúc và i đã đạt giá trị 3! // ====== 2. CÁCH SỬA CHUẨN XÁC BẰNG LET ====== for (let j = 0; j < 3; j++) { setTimeout(function () { console.log("Giá trị của j (dùng let):", j); }, 1000); } // KẾT QUẢ IN RA CONSOLE SAU 1 GIÂY: // Giá trị của j (dùng let): 0 // Giá trị của j (dùng let): 1 // Giá trị của j (dùng let): 2 // GIẢI THÍCH: 'let' có Block Scope. Mỗi vòng lặp for sẽ tạo ra một môi trường phạm vi mới (lexical scope) // và một biến 'j' hoàn toàn độc lập, lưu giữ đúng giá trị của vòng lặp đó!

4. Hướng dẫn các bước Debug chuyên nghiệp bằng Chrome DevTools

Khi code JavaScript bị lỗi logic hoặc chạy không như ý muốn, các bước gỡ lỗi chuẩn trên trình duyệt Google Chrome bao gồm:

  1. Bước 1: Mở công cụ lập trình viên: Nhấn phím F12 (hoặc tổ hợp phím Ctrl + Shift + I trên Windows, hoặc chuột phải chọn Inspect / Kiểm tra).
  2. Bước 2: Chuyển sang thẻ Sources: Tại thanh tab phía trên của DevTools, bấm chọn tab Sources. Ở cây thư mục bên trái, tìm và click mở file script cần gỡ lỗi (ví dụ: js/script.js).
  3. Bước 3: Đặt điểm dừng (Breakpoint): Nhấp chuột trái vào số thứ tự dòng code nghi ngờ bị lỗi (ví dụ dòng lệnh bên trong vòng lặp for hoặc sự kiện click). Dòng đó sẽ hiện một cờ đánh dấu màu xanh lam.
  4. Bước 4: Thực thi và quan sát biến: Quay lại trang web thao tác kích hoạt sự kiện (như bấm nút Submit, nhập tìm kiếm...). Trình duyệt sẽ tạm ngưng thực thi ngay tại dòng Breakpoint:
    • Nhìn sang khung Scope ở thanh bên phải để theo dõi giá trị thực tế của các biến cục bộ (Local/Block) và biến toàn cục (Global).
    • Chuyển qua tab Console ở dưới để gõ thử các biểu thức tính toán hoặc in biến ra màn hình ngay tại thời điểm dừng.
    • Dùng các phím điều hướng: F10 (Step over - nhảy qua dòng tiếp theo), F11 (Step into - đi vào trong hàm con), F8 (Resume script execution - tiếp tục chạy code).

CÂU 4: KHÁI NIỆM EVENT DELEGATION & EVENT BUBBLING TRONG JAVASCRIPT

1. Khái niệm và nguyên lý hoạt động

Event Bubbling (Cơ chế nổi bọt sự kiện): Trong mô hình DOM, khi một sự kiện xảy ra trên một phần tử con cụ thể (ví dụ click chuột vào thẻ <li> hoặc thẻ <button>), sự kiện đó sẽ không chỉ dừng lại ở phần tử con đó mà sẽ tự động "nổi bọt" lan truyền dần ngược lên các phần tử cha, ông bà, tổ tiên chứa nó (từ <li> → <ul> → <div> → <body> → <html> → document → window).

Event Delegation (Kỹ thuật ủy quyền sự kiện): Lợi dụng cơ chế nổi bọt ở trên, thay vì phải đi tìm và gắn từng bộ lắng nghe sự kiện (addEventListener) lên hàng chục hoặc hàng trăm phần tử con riêng lẻ, lập trình viên chỉ cần gắn DUY NHẤT một bộ lắng nghe sự kiện lên phần tử cha chung. Khi người dùng click vào bất kỳ phần tử con nào bên trong, sự kiện sẽ nổi bọt lên cha, và tại thẻ cha ta chỉ cần kiểm tra e.target để biết chính xác phần tử con nào vừa được tác động.

2. Ví dụ code minh họa: Quản lý danh sách động <ul> và các thẻ <li>

<!-- Giao diện HTML --> <button id="btnAdd">Thêm việc cần làm mới</button> <ul id="todoList"> <li class="todo-item">Bài học 1: HTML5 Semantics</li> <li class="todo-item">Bài học 2: CSS Flexbox & Grid</li> </ul> <script> // 1. LẤY PHẦN TỬ CHA const todoList = document.getElementById("todoList"); const btnAdd = document.getElementById("btnAdd"); let counter = 3; // 2. GẮN DUY NHẤT 1 SỰ KIỆN LÊN THẺ CHA <ul> (ỦY QUYỀN SỰ KIỆN) todoList.addEventListener("click", function (event) { // event.target là phần tử thực sự người dùng vừa click vào const clickedItem = event.target.closest(".todo-item"); if (clickedItem) { // Đổi màu nền để đánh dấu đã hoàn thành clickedItem.style.textDecoration = "line-through"; clickedItem.style.color = "#94a3b8"; console.log("Đã click vào mục:", clickedItem.textContent); } }); // 3. THÊM CÁC THẺ <li> MỚI ĐỘNG BẰNG JAVASCRIPT btnAdd.addEventListener("click", function () { const newLi = document.createElement("li"); newLi.className = "todo-item"; newLi.textContent = "Bài học " + counter + ": JavaScript Nâng cao"; todoList.appendChild(newLi); counter++; // LƯU Ý QUAN TRỌNG: Chúng ta KHÔNG CẦN phải viết addEventListener cho newLi này! // Nhờ có Event Delegation ở thẻ cha #todoList, newLi mới sinh ra vẫn nhận sự kiện bình thường! }); </script>

3. Ba ưu điểm vượt trội của Event Delegation

  • 1. Tiết kiệm tối đa bộ nhớ RAM của trình duyệt: Thay vì tạo hàng ngàn hàm callback riêng biệt trong bộ nhớ cho từng hàng bảng dữ liệu (<tr>) hay từng mục danh sách (<li>), ứng dụng chỉ tốn bộ nhớ cho duy nhất 1 listener ở thẻ cha. Giúp trang web nhẹ hơn và hoạt động mượt mà hơn.
  • 2. Quản lý các phần tử được sinh ra động (Dynamic Elements) dễ dàng: Trong các ứng dụng hiện đại khi dữ liệu tải từ API về và render liên tục, nếu không dùng Event Delegation, các thẻ mới sinh ra sẽ không có sự kiện gắn kèm và bắt buộc phải viết code gắn lại rất cồng kềnh. Event Delegation giải quyết triệt để vấn đề này.
  • 3. Mã nguồn gọn gàng, giảm thiểu rủi ro rò rỉ bộ nhớ (Memory Leak): Giảm số lượng listener cần theo dõi và giải phóng, hạn chế tối đa nguy cơ các listener mồ côi (orphaned listeners) tồn tại ngầm trong bộ nhớ khi các phần tử con bị xóa khỏi DOM.
